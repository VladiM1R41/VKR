## 1. Зачем этот источник

CNews — одно из самых известных российских IT- и digital-медиа. Покрывает:
- корпоративный IT
- цифровизацию
- ИБ
- телеком
- софт
- железо
- рынок технологий

Что даёт `Jarvis`:
- Тематику, которой у вас пока относительно мало: `corporate tech / telecom / digital business`
- Хорошее дополнение к `Хабру` и `iXBT`
  - `Хабр` даёт сообщество и длинную экспертизу
  - `iXBT` даёт tech-новости и гаджеты
  - `CNews` даёт именно деловую технологическую повестку
- Узнаваемый российский бренд, хорошо подходящий для `MVP`

Рекомендуемая роль в проекте:
- `MVP`

## 2. Юридический статус

Источник правил:
- условия использования материалов CNews

Ключевые выводы:
- Использование материалов сайта возможно только с письменного разрешения ООО «Синьюс»
- Отдельно запрещено использование материалов по п.3 ч.1 ст.1274 ГК РФ без разрешения
- Цитирование допускается безвозмездно в объёме, оправданном целью цитирования, но не более `1000` знаков
- Обязательны:
  - гиперссылка на исходную публикацию
  - текстовое упоминание `CNews` как источника

Для ВКР:
- Допустимо использовать RSS и HTML-страницы для внутреннего анализа и retrieval
- Допустимо использовать статьи как контекст для `RAG`
- В продукте обязательно нужен пересказ и ссылка на оригинал
- Нельзя воспроизводить текст статьи в заметных объёмах пользователю

Нормализованное значение для БД:
- `legal_status = "restricted"`

Примечание:
- Источник полезный и тематически очень сильный, но по правовому режиму более строгий, чем `BFM`

## 4. Что реально отдаёт источник

### 4.1. Структура ответа

По предоставленному живому RSS:

```xml
<item>
  <guid>https://www.cnews.ru/news/line/2026-04-06_avito_spros_na_kompleksnye</guid>
  <link>https://www.cnews.ru/news/line/2026-04-06_avito_spros_na_kompleksnye</link>
  <title>«Авито»: спрос на комплексные услуги грузчиков вырос почти в 1,5 раза</title>
  <pubDate>Mon, 06 Apr 2026 18:52:00 +0300</pubDate>
  <description><![CDATA[
    Россияне все чаще доверяют профессионалам не только физическую транспортировку вещей, но и сопутствующие работы...
  ]]></description>
  <enclosure url="" type="image/jpeg"/>
</item>
```

### 4.2. Ключевые наблюдения

- `guid` и `link` совпадают
- URL статьи выглядит чистым и каноничным
- `description` содержит короткий лид, не полный текст
- `author` в RSS отсутствует
- `category` в примере отсутствует
- `enclosure` присутствует, но `url=""` пустой, то есть как источник thumbnail в текущем виде бесполезен
- в фиде `200` записей
- RSS поддерживает `ETag` и `Last-Modified`
- `pubDate` приходит в `+0300`, значит в БД сохраняем UTC

### 4.3. Поля, которые надо брать в коллектор

| Поле Jarvis | Откуда брать |
|-------------|--------------|
| `url` | `entry.link` |
| `canonical_url` | нормализованный `entry.link` |
| `title` | `entry.title` |
| `content` | full text со страницы статьи |
| `snippet_lead` | `entry.summary` / `description` |
| `published_at` | `entry.published_parsed` |
| `author` | `null` если не найден на HTML |
| `tags` | пока не подтверждены |
| `thumbnail` | не из RSS, нужно искать на HTML-странице |
| `raw_content` | HTML страницы статьи |

## 5. robots.txt и техническая вежливость

Источник:
- `https://www.cnews.ru/robots.txt`

Ключевые директивы:

```txt
User-Agent: *
Disallow: /main/
Disallow: /news/for_blog/
Disallow: /articles/for_blog/
Disallow: /news/for_print/
Disallow: /articles/for_print/
Disallow: /articles/preview/
Disallow: /news/preview/
Disallow: /redirect.php
Disallow: /search

Host: https://www.cnews.ru
Sitemap: https://www.cnews.ru/inc/sitemap.xml
```

Что это значит для нас:

| Директива | Значение | Действие коллектора |
|-----------|----------|---------------------|
| `/news/line/...` не в `Disallow` | страницы новостей разрешены | можно ходить за полным текстом |
| `/search` запрещён | поиск нельзя использовать | не трогать |
| `/preview`, `/for_print`, `/for_blog` запрещены | служебные и альтернативные версии | не использовать |
| `Crawl-delay` отсутствует | явного ограничения нет | использовать `crawl_delay = 1.0` |

Итог:
- За HTML-страницами новостей ходить можно
- RSS и прямые страницы новостей выглядят пригодными для сбора

## 6. Извлечение полного текста

Нужно ли идти на страницу:
- `да`

Рекомендуемая стратегия:
1. Сохранить `description` как `snippet_lead`
2. Скачать HTML страницы статьи по `canonical_url`
3. Попробовать `trafilatura.bare_extraction(..., favor_precision=True)`
4. Если текста мало, попробовать `favor_recall=True`
5. Если extraction слабый — искать CSS-блоки статьи через `BeautifulSoup`

Что подтверждено тестом:
- HTML статический
- `trafilatura` хорошо извлекает полный текст
- `Playwright` не нужен
- автора на странице тестом не найдено
- `og:image` на странице есть, но в проверенной статье это placeholder, а не полезная иллюстрация

Что пока не подтверждено:
- есть ли paywall на других типах материалов
- есть ли стабильный небесполезный thumbnail на большинстве страниц
- нужен ли отдельный BS4 fallback

## 9. Мониторинг здоровья

Что может сломаться:
- RSS перестанет отдавать корректные `description`
- HTML-страницы могут изменить структуру статьи
- `trafilatura` может начать захватывать рекламные или сайдбар-блоки
- поддоменные CNews-фиды могут расходиться по структуре

Минимальные health-check сигналы:
- RSS отвечает `200`
- в фиде есть записи
- даты парсятся
- HTML статьи доступен
- full text хотя бы одной статьи извлекается

Нормальные значения:
- `items в фиде`: `200`
- `ETag`: поддерживается
- `Last-Modified`: поддерживается
- `author coverage`: `0/200`
- `thumbnail availability`:
  - RSS: `0/200` полезных
  - HTML: `og:image` может быть placeholder
- `content length` на проверенной статье: `5128` символов

## 10. Итоговые правила для коллектора

```text
1. Забрать RSS по URL https://www.cnews.ru/inc/rss/news.xml
2. Для URL статьи использовать entry.link
3. Для canonical_url использовать обычную нормализацию URL
4. snippet_lead брать из description
5. За полным текстом ходить на HTML-страницу статьи
6. Для full text сначала использовать trafilatura, при необходимости добавить BS4 fallback
7. Не рассчитывать на enclosure как на источник thumbnail — url пустой
8. Не считать og:image автоматически полезным thumbnail, потому что он может быть placeholder
9. При плохом extraction всё равно сохранять новость с snippet_lead
```
