## 3. Тип источника и доступ

| Параметр | Значение |
|----------|----------|
| Тип | RSS |
| Протокол | HTTPS, pull-режим |
| Аутентификация | Не нужна (публичный RSS) |
| Полный текст в RSS | **ДА** — через `/rss/yandex.xml` (Яндекс.Турбо формат) |
| Нужен Playwright | Нет — полный текст уже в RSS |

### RSS URL — используем Яндекс-фид

```
https://tass.ru/rss/yandex.xml   ← ОСНОВНОЙ (полный текст в RSS!)
https://tass.ru/rss/v2.xml       ← резервный (описание непостоянное)
```

**Почему Яндекс-фид лучше:**
- `<yandex:full-text>` — полный HTML статьи прямо в RSS
- `<description>` — всегда присутствует (в v2.xml был непостоянным)
- `<enclosure>` — thumbnail у части статей
- Требует **1 HTTP запрос** вместо 1 (RSS) + 100 (страницы)
- Меньше нагрузки на сервер ТАСС → более этично

**Доступность:** URL публично доступен (не в Disallow для `User-agent: *`).
`Allow: /rss/yandex.xml` в robots.txt — это разрешение для YandexNews,
но не запрет для остальных.

Альтернативные URL (если яндекс-фид перестанет работать):
- `https://tass.ru/rss/v2.xml` — основной публичный RSS
- `https://tass.ru/feed`
- `https://tass.ru/rss/google.xml`

## 4. Что реально отдаёт RSS (исследование живого фида)

**Проверено:** `https://tass.ru/rss/yandex.xml` и `https://tass.ru/rss/v2.xml` (апрель 2026)

### Яндекс-фид (`/rss/yandex.xml`) — ОСНОВНОЙ

Структура `<item>`:

```xml
<item>
  <title>В Белгородской области при атаке ВСУ пострадал мужчина</title>
  <category>Происшествия</category>

  <!-- нет <guid>! используем <link> для дедупликации -->
  <link><![CDATA[ https://tass.ru/proisshestviya/26998073 ]]></link>
  <pdalink><![CDATA[ https://tass.ru/proisshestviya/26998073 ]]></pdalink>

  <!-- pubDate в МОСКОВСКОМ ВРЕМЕНИ (+0300), НЕ UTC -->
  <pubDate>Fri, 03 Apr 2026 21:44:49 +0300</pubDate>

  <!-- description ВСЕГДА ЕСТЬ (в yandex-фиде) -->
  <description>БЕЛГОРОД, 3 апреля. /ТАСС/. Вооруженные силы Украины атаковали...</description>

  <!-- полный HTML текста статьи — главная ценность этого фида! -->
  <yandex:full-text><![CDATA[
    <p>БЕЛГОРОД, 3 апреля. /ТАСС/. Вооруженные силы...</p>
    <p>"Четыре муниципалитета под ударами ВСУ..."</p>
  ]]></yandex:full-text>

  <yandex:genre>message</yandex:genre>
  <yandex:theme_tags>...</yandex:theme_tags>

  <!-- thumbnail присутствует у части статей -->
  <enclosure url="https://cdn-media.tass.ru/..." type="image/jpeg" length="..."/>
</item>
```

### Резервный фид (`/rss/v2.xml`)

```xml
<item>
  <title>...</title>
  <link><![CDATA[ https://tass.ru/ekonomika/26997867 ]]></link>
  <guid><![CDATA[ https://tass.ru/ekonomika/26997867 ]]></guid>  ← есть guid!
  <pubDate>Fri, 03 Apr 2026 21:05:28 +0300</pubDate>
  <description>лид или пусто (непостоянно)</description>
  <category>Экономика и бизнес</category>
  <!-- нет yandex:full-text → нужен отдельный HTTP-запрос на страницу -->
</item>
```

### Сравнение фидов

| Параметр | `/rss/yandex.xml` | `/rss/v2.xml` |
|---|---|---|
| Записей в фиде | **916** (~9 дней) | ~100 (1 день) |
| Размер | **2.9 MB** | ~0.2 MB |
| `full-text` в RSS | **100%** | нет |
| `description` | **100%** | ~50-70% (непостоянно) |
| `<guid>` | **НЕТ** (есть `<pdalink>`) | есть |
| Thumbnail | у части статей | нет |
| Нужен скрапинг | **НЕТ** | да (1 запрос/статью) |
| ETag/Last-Modified | нет | нет |

### Ключевые наблюдения

**`<yandex:full-text>` — полный HTML прямо в RSS (100% items).**
feedparser не парсит этот namespace — извлекаем вручную через ElementTree.
BeautifulSoup конвертирует HTML → чистый текст.

**916 записей — глубокий архив (~9 дней).**
При первом запуске это backfill за неделю с лишним.
При последующих опросах большинство будет отсеяно дедупликацией.

**Нет ETag/Last-Modified у обоих фидов.**
Каждый опрос скачивает полный фид. При 30-минутном интервале:
- yandex.xml: 2.9MB × 48 = ~140 MB/день трафика (только RSS)
- v2.xml: 0.2MB × 48 = ~10 MB/день
Применяем `stop_early`: прекращаем обработку когда встречаем уже известную статью.

**Нет `<guid>` в яндекс-фиде.**
feedparser возвращает `entry.id = ''`. Используем `entry.link` для дедупликации.
Canonical URL: нормализация `<link>` (https, без trailing slash). UTM нет.

**`<pubDate>` в `+0300` (московское время).**
feedparser конвертирует в UTC автоматически. `calendar.timegm()` корректен.

**`<author>` отсутствует.**
ТАСС — агентство, нет подписи конкретного журналиста.

**`<category>` — несколько рубрик на статью.**
«Происшествия», «В мире», «Экономика и бизнес», «Москва» и т.д.

## 5. robots.txt (исследование)

Источник: `https://tass.ru/robots.txt` (апрель 2026)

```
User-agent: YandexNews
Allow: /rss/yandex.xml

User-agent: *
Disallow: /search
Disallow: /preview/
Disallow: /n/
Disallow: */api/*
Disallow: /video/
```

### Что это значит для нас

| Директива | Что значит | Наше действие |
|-----------|-----------|---------------|
| **Нет Crawl-delay** | Явного ограничения нет | Используем `crawl_delay = 1.0` (вежливый дефолт) |
| `Disallow: */api/*` | API-эндпоинты закрыты | Нас не касается, мы читаем RSS |
| `Disallow: /video/` | Видео-раздел закрыт | Нас не касается |
| `Disallow: /preview/` | Превью закрыты | Нас не касается |
| Страницы статей | НЕ в Disallow | Ходить за полным текстом можно |
| `Allow: /rss/yandex.xml` | Специальный RSS для Яндекса | Возможно более полный — проверить |

**Вывод:** robots.txt ходить на страницы статей не запрещает.
Юридические ограничения — в Правилах использования (см. раздел 2), не в robots.txt.

## 6. Путь одной статьи: от RSS до базы

```
[Попытка 1: Яндекс-фид]
  │
  ├── GET https://tass.ru/rss/yandex.xml
  │   Если ошибка (404, 403, timeout) → переключиться на v2.xml
  │
  ├── Парсинг:
  │   feedparser → стандартные поля (title, link, pubDate, category)
  │   ElementTree → yandex:full-text (HTML → BeautifulSoup → чистый текст)
  │
  └── Для каждого <item> (от новых к старым):
      │
      ├── Canonical URL ← entry.link (нет guid в яндекс-фиде!)
      │
      ├── Дедупликация: canonical_url уже в базе? → СТОП (все дальше тоже старые)
      │
      ├── Контент:
      │   full_text ← yandex:full-text → BeautifulSoup.get_text()
      │   Если full_text пустой → fallback: description
      │   Если оба пусты → статья без контента (редко)
      │   HTTP-запрос на страницу НЕ нужен!
      │
      └── Сохранить
          INSERT INTO news (url, canonical_url, title, content, snippet_lead,
                            published_at, source_id, ...)
          INSERT INTO news_raw (raw_content=full_text_html, raw_format='html_fragment')
          extra JSONB: {"categories": [...], "thumbnail": "...", "extraction_method": "yandex_full_text"}

[Fallback: обычный фид v2.xml]
  │  (если яндекс-фид недоступен)
  │
  ├── GET https://tass.ru/rss/v2.xml
  │
  └── Для каждого <item>:
      ├── Полный текст: GET на canonical_url, crawl_delay=1.0 сек
      │   trafilatura → если пусто → description fallback
      └── Сохранить (тот же формат)
```

### Логика переключения фидов в коде

```python
TASS_FEEDS = [
    ("https://tass.ru/rss/yandex.xml", "yandex"),   # основной: full-text в RSS
    ("https://tass.ru/rss/v2.xml",     "v2"),        # резерв: нужен скрапинг страниц
]

async def collect_tass(source):
    for feed_url, feed_type in TASS_FEEDS:
        try:
            raw = await fetch_feed(feed_url)
            return await parse_tass_feed(raw, feed_type, source)
        except Exception as e:
            log.warning(f"TASS {feed_type} feed failed: {e}, trying next...")
    log.error("All TASS feeds failed")
    return []
```

## 7. Извлечение полного текста

**Основной путь (яндекс-фид):**
`yandex:full-text` содержит готовый HTML фрагмент.
ElementTree извлекает HTML → BeautifulSoup.get_text() → чистый текст.
HTTP-запрос на страницу статьи НЕ нужен.

**Резервный путь (v2.xml):**
Статический HTML, Playwright не нужен. trafilatura справляется хорошо.

**Особенности текстов ТАСС:**
- Короткие (200-800 символов) — информационные сводки в 3-5 предложений
- Формат: «ГОРОД, дата. /ТАСС/. Текст новости.»
- Иногда большие цитаты (речи официальных лиц)
- Нет paywall

## 8. Расписание опроса

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| `crawl_interval` | 30 минут | Нет ETag: яндекс-фид 2.9MB за раз. 30 мин = ~140MB/день |
| `crawl_delay` | 0 | Весь контент в RSS, на страницы не ходим |
| `priority` | `high` | Оперативные новости, breaking news |

**Расчёт трафика:**
- 30 мин интервал: 2.9MB × 48 = ~140 MB/день (только RSS, без скрапинга страниц)
- 15 мин интервал: 2.9MB × 96 = ~280 MB/день
- 60 мин интервал: 2.9MB × 24 = ~70 MB/день

**Стратегия stop_early** (без ETag это важно):
Сортировать items от новых к старым. Прекратить обработку как только встретили
`canonical_url` уже известный базе. Все остальные тоже старые — не обрабатывать.

**~100 новостей/день:** при 30-минутных опросах ожидаем ~2 новых статьи за опрос.
Из 916 items в фиде нужно обработать только 2. Остальные 914 — пропустить быстро.

## 9. Мониторинг здоровья

**Что может сломаться:**
- ТАСС иногда блокирует ботов по IP или User-Agent → мониторить HTTP статусы
- Структура HTML статей изменится → trafilatura перестанет работать
- Правила использования изменятся (они обновляются без уведомления!)

**Метрики здоровья:**
- `articles_last_24h` — норма: 80-120. Если 0 → проблема
- `avg_content_length` — норма для ТАСС: 200-2000 символов (короткие сводки)
- `http_errors_last_24h` — если >10% запросов возвращают 403/429 → бот заблокирован
