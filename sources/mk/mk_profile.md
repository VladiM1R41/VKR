> Составлено на основе исследования: живого RSS-фида, правил использования материалов и `robots.txt`.
> Дата последней проверки: `2026-04-07`

## 1. Зачем этот источник

`МК` полезен для `Jarvis` как очень массовый и узнаваемый российский новостной источник с широким тематическим и региональным покрытием:
- политика
- общество
- происшествия
- спорт
- культура
- региональные новости

Что дает проекту:
- усиливает широкий федерально-региональный новостной контур
- добавляет региональные поддомены в одном общем потоке
- дает более массовую общественную повестку, чем `РБК`, `BFM`, `CNews`

Рекомендуемая роль в проекте:
- `MVP`

## 2. Юридический статус

Источник правил:
- notice на главной странице `mk.ru` о соблюдении авторских прав

Ключевые выводы:
- все права на материалы, опубликованные на `mk.ru`, принадлежат редакции
- использование материалов допускается только с письменного разрешения правообладателя
- обязательна прямая гиперссылка на страницу, с которой материал заимствован
- гиперссылка должна размещаться непосредственно рядом с цитируемым блоком

Для ВКР:
- допустимо использовать RSS и HTML для внутреннего анализа, индексации и retrieval
- в пользовательском продукте нужно ориентироваться на пересказ и ссылку на оригинал
- нельзя рассчитывать на свободное полнотекстовое воспроизведение материала

Нормализованное значение для БД:
- `legal_status = "restricted"`

Примечание:
- источник очень полезен по охвату, но по авторским правам строгий

## 4. Что реально отдает источник

### 4.1. Структура RSS

По предоставленному живому RSS:

```xml
<item>
  <title>Трамп предрек конец Ирану</title>
  <link>https://www.mk.ru/politics/2026/04/07/tramp-predrek-konec-iranu.html</link>
  <description>Президент США Дональд Трамп написал...</description>
  <category>Политика</category>
  <enclosure url="https://static.mk.ru/upload/entities/...jpg" type="image/jpeg" length="190802"/>
  <pubDate>Tue, 07 Apr 2026 15:25:27 +0300</pubDate>
</item>
```

### 4.2. Ключевые наблюдения

- RSS отдает новости как с основного домена `www.mk.ru`, так и с региональных поддоменов
- `category` присутствует и выглядит полезной рубрикой
- `enclosure` присутствует и, в отличие от `CNews`, выглядит полезным источником thumbnail
- у некоторых записей может быть несколько `enclosure`
- `guid` отсутствует
- `author` в RSS отсутствует
- есть `ttl = 2`, что намекает на частое обновление ленты
- `lastBuildDate` присутствует

### 4.3. Поля, которые брать в коллектор

| Поле Jarvis | Откуда брать |
|-------------|--------------|
| `url` | `entry.link` |
| `canonical_url` | нормализованный `entry.link` |
| `title` | `entry.title` |
| `content` | full text со страницы статьи |
| `snippet_lead` | `entry.summary` / `description` |
| `published_at` | `entry.published_parsed` |
| `author` | `null`, автора не считать надежным полем |
| `tags` | можно начать с `category` |
| `thumbnail` | первый валидный `enclosure.url`, при необходимости сверять с `og:image` |
| `raw_content` | HTML страницы статьи |

## 5. robots.txt и техническая вежливость

Источник:
- `https://www.mk.ru/robots.txt`

Ключевые директивы:

```txt
User-agent: *
Disallow: /search/
Disallow: /system/
Disallow: /upload/adv/
Disallow: /admin/
Disallow: /advert/preview/
Disallow: /finance/redirect/
Disallow: *couponRedirect
Disallow: /print/
Sitemap: https://www.mk.ru/sitemap/index.xml
```

Что это значит для нас:

| Директива | Значение | Действие коллектора |
|-----------|----------|---------------------|
| страницы статей явно не запрещены | HTML новостей, вероятно, разрешен | можно тестировать full-text fetch |
| `/print/` запрещен | печатные версии не использовать | брать только обычные article URL |
| `Clean-param` есть | параметры URL нужно чистить | canonicalization обязательна |
| `Crawl-delay` отсутствует | жесткого лимита нет | стартово использовать `crawl_delay = 1.0` |

Итог:
- с точки зрения `robots.txt` источник выглядит удобным для обычного RSS + HTML сбора

## 6. Извлечение полного текста

Нужно ли идти на страницу:
- `да`

Рекомендуемая стратегия:
1. сохранить `description` как `snippet_lead`
2. скачать HTML статьи по `canonical_url`
3. попробовать `trafilatura.bare_extraction(..., favor_precision=True)`
4. если текста мало, попробовать `favor_recall=True`
5. если extraction слабый, искать HTML-контейнер статьи через `BeautifulSoup`

Что ожидаем:
- HTML, вероятно, статический
- `trafilatura` должна справиться, но это надо проверить
- на HTML, возможно, можно достать автора и дополнительные метаданные

Что подтверждено тестом:
- HTML статический
- `trafilatura` дает хороший full text
- `Playwright` не нужен
- `og:image` на странице совпадает с RSS thumbnail
- автора не стоит считать надежным полем: на части страниц он может быть, на части отсутствовать

Что пока не подтверждено:
- есть ли шумовые блоки на других типах страниц

## 7. Дедупликация и каноникализация

Предварительные правила:
- использовать `link` как основной URL статьи
- чистить query-параметры по `Clean-param` из `robots.txt`
- сохранять домен как часть сигнала источника, потому что в ленте есть региональные поддомены

Итог:
- `canonical_url` строится из `entry.link`
- `title_hash` использовать как второй уровень дедупликации
- полезно сохранять `source_host`, чтобы видеть распределение по региональным поддоменам

## 9. Мониторинг здоровья

Что может сломаться:
- RSS может перестать отдавать полезный `enclosure`
- HTML-структура статьи может измениться
- `trafilatura` может начать захватывать боковые блоки
- региональные поддомены могут иметь отличающуюся структуру страниц

Минимальные health-check сигналы:
- RSS отвечает `200`
- в фиде есть записи
- даты парсятся
- `category` присутствует хотя бы у части записей
- `enclosure` присутствует хотя бы у части записей
- HTML статьи доступен

Нормальные значения:
- `items в фиде`: `75`
- `ETag`: не поддерживается
- `Last-Modified`: не поддерживается
- `category coverage`: `75/75`
- `enclosure coverage`: `73/75`
- `guid coverage`: `0/75`
- `author coverage in RSS`: `0/75`
- `unique hosts`: `36`
- `full-text quality`: `ok`, на тестовой статье `716` символов
- `lastBuildDate` есть и может использоваться как вспомогательный сигнал свежести фида

## 10. Итоговые правила для коллектора

```text
1. Забрать RSS по URL https://www.mk.ru/rss/index.xml
2. Для URL статьи использовать entry.link
3. Для canonical_url чистить query-параметры
4. snippet_lead брать из description
5. category использовать как первичный tag / rubric
6. thumbnail брать из первого валидного enclosure.url
7. За полным текстом ходить на HTML-страницу статьи
8. Автора для MK пока не считать надежным полем и не строить на нем логику коллектора
9. Сохранять host статьи, потому что в ленте смешаны основной домен и региональные поддомены
10. lastBuildDate можно использовать как дополнительный cheap-signal обновления фида, но не вместо нормальной дедупликации по URL/title
11. В итоговом продукте использовать пересказ и ссылку, а не большие куски оригинала
```
