## 1. Зачем этот источник

Life.ru — российский новостной портал с быстрым потоком коротких новостей. Покрывает:
политику, общество, СВО, спорт, лайфстайл, религиозные темы.

Что даёт `Jarvis`:
- Быструю общественно-политическую ленту
- Широкую тематику, отличную от чисто деловых и технологических источников
- Готовый `snippet_lead` из RSS без HTML-очистки
- `thumbnail` почти у каждой новости через `<enclosure>`
- Несколько `<category>` на одну запись, что полезно для Слоя 2

Рекомендуемая роль в проекте:
- `MVP`, но с умеренным `trust_score`, потому что это не информагентство, а таблоидный источник

## 2. Юридический статус

Источник правил:
- `https://life.ru/`
- пользовательское соглашение сайта

Ключевые выводы:
- Пользовательское соглашение в основном регулирует пользовательский контент и поведение пользователей
- Прямого запрета на чтение публичного RSS-фида не выявлено
- RSS открыт без авторизации и явно предназначен для распространения контента в машиночитаемом виде
- Полные тексты статей не стоит воспроизводить пользователю как есть; в продукте нужен пересказ и ссылка на оригинал

Для ВКР:
- Допустимо читать RSS и открытые HTML-страницы для внутреннего анализа
- Допустимо использовать статьи как контекст для `RAG`
- Допустимо формировать дайджесты с обязательной ссылкой на оригинал
- Недопустимо коммерческое переиспользование контента без отдельного согласования

Нормализованное значение для БД:
- `legal_status = "public_rss"`

Примечание:
- В старом профиле использовалось значение `open`, но для согласованности со схемой БД лучше фиксировать именно `public_rss`

## 4. Что реально отдаёт источник

### 4.1. Структура ответа

Проверено на живом RSS-фиде в апреле 2026.

```xml
<item>
  <title>Сальдо перечислил ключевые точки фронта в Херсонской области</title>
  <description>По словам главы Херсонской области Владимира Сальдо, линия боевого...</description>
  <link>https://life.ru/p/1859768</link>
  <guid>https://life.ru/p/1859768</guid>
  <pubDate>Sat, 04 Apr 2026 15:13:11 +0300</pubDate>
  <category>Владимир Сальдо</category>
  <category>Специальная военная операция (СВО)</category>
  <category>ВС РФ</category>
  <category>ВСУ</category>
  <enclosure
      url="https://static.life.ru/publications/2026/3/28/1365285728232.7505.jpeg"
      length="0"
      type="image/jpeg"/>
</item>
```

### 4.2. Ключевые наблюдения

- `link` и `guid` совпадают, оба уже чистые и без UTM-параметров
- URL статьи короткий: `https://life.ru/p/{id}`
- `description` содержит готовый текстовый лид, а не HTML
- `author` отсутствует
- `content:encoded` отсутствует
- `<category>` может встречаться несколько раз; это полезные теги
- `<enclosure>` содержит `thumbnail`, даже если `length="0"`
- `pubDate` приходит в `+0300`, `feedparser` плюс `calendar.timegm()` дают корректный UTC
- HTML статьи статический, `trafilatura` справляется без браузерного рендеринга

### 4.3. Поля, которые надо брать в коллектор

| Поле Jarvis | Откуда брать |
|-------------|--------------|
| `url` | `entry.link` |
| `canonical_url` | нормализованный `entry.link` |
| `title` | `entry.title` |
| `content` | full text со страницы статьи |
| `snippet_lead` | `entry.summary` / `description` |
| `published_at` | `entry.published_parsed` |
| `author` | `null` |
| `tags` | все `entry.tags[*].term` |
| `thumbnail` | `entry.enclosures[0].href` |
| `raw_content` | HTML страницы статьи |

## 5. robots.txt и техническая вежливость

Источник:
- `https://life.ru/robots.txt`

Ключевые директивы:

```txt
User-agent: *
Disallow: /search
Disallow: /preview*
Disallow: /xml/feed.xml?*
Disallow: *?*
Allow: /.css
Allow: /.js
Allow: /.jpg
Sitemap: https://life.ru/sitemap.xml.gz
```

Что это значит для нас:

| Директива | Значение | Действие коллектора |
|-----------|----------|---------------------|
| `Disallow: *?*` | любые URL с query params запрещены | использовать только чистые URL статьи без `?` |
| `/p/{id}` не в `Disallow` | страницы статей разрешены | можно ходить за полным текстом |
| `Crawl-delay` отсутствует | явного ограничения нет | использовать вежливый дефолт `crawl_delay = 1.0` |
| `/search`, `/preview*` запрещены | служебные страницы | не трогать |

Итог:
- За полным текстом на HTML-страницы ходить можно
- RSS-фид использовать как основной источник discovery
- Любые URL с query parameters недопустимы
- Достаточно честного `User-Agent`: `JarvisNewsBot/1.0 (academic-research)`

## 6. Извлечение полного текста

Нужно ли идти на страницу:
- `да`

Рекомендуемая стратегия:
1. Взять `description` как `snippet_lead`
2. Скачать HTML статьи по `canonical_url`
3. Попробовать `trafilatura.bare_extraction(..., favor_precision=True)`
4. Если текста мало, попробовать `favor_recall=True`
5. Если и после этого текста мало, сохранить хотя бы `description` и пометить качество как пониженное

Что работает хорошо:
- `trafilatura` извлекает текст без `Playwright`
- HTML статический
- Life.ru публикует короткие заметки, поэтому длина `400-700` символов может быть нормой, а не признаком поломки

Что может ломаться:
- Короткая статья может быть ошибочно принята за paywall или JS-рендеринг
- BS4-fallback пока не найден и не подтверждён

Особые правила очистки:
- `description` не нужно парсить как HTML
- `thumbnail` брать из `enclosure`, а не искать в HTML
- `author` всегда оставлять `null`, пока источник его не начнёт отдавать

## 7. Дедупликация и каноникализация

Правила для этого источника:
- `link` уже чистый, без UTM и query params
- `guid` совпадает с `link`, можно использовать любой, но достаточно `link`
- каноникализация нужна только для приведения схемы к `https`, удаления `www.` и trailing slash
- риск дублей между фидами неактуален, так как используется один основной RSS

Итог:
- `canonical_url` строится из `entry.link`
- `title_hash` полезен как дополнительная страховка, но основной уровень дедупликации здесь URL
- `event_cluster_id` у большинства записей будет уникальным, пока не сравниваем с другими источниками

## 9. Мониторинг здоровья

Что может сломаться:
- RSS перестанет отвечать
- исчезнут `enclosure` или `category`
- `trafilatura` перестанет извлекать полный текст
- резко просядет средняя длина `content`

Минимальные health-check сигналы:
- RSS отвечает `200`
- фид содержит записи
- даты корректно парсятся
- `description` не пустой
- full text хотя бы из одной статьи извлекается

Нормальные значения:
- `items в фиде`: около `200`
- `avg_content_length`: ориентир `400-700` символов для коротких новостей
- `thumbnail coverage`: близко к `100%`

## 10. Итоговые правила для коллектора

```text
1. Забрать RSS по URL https://life.ru/rss
2. Для URL статьи брать entry.link
3. Для canonical_url использовать нормализацию link без query params
4. snippet_lead брать прямо из description — это уже чистый текст
5. За полным текстом ходить на HTML-страницу статьи
6. Для текста использовать trafilatura; сначала precision, потом recall
7. В metadata сохранять tags, thumbnail, extraction_method
8. Author не заполнять — источник его не отдаёт
9. При неудачном full-text extraction всё равно сохранять новость с snippet_lead
```
