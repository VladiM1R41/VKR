## 1. Зачем этот источник

- экономику
- финансы
- рынки
- политику
- бизнес-повестку

Что даёт `Jarvis`:

## 2. Юридический статус

Источник правил:
- условия использования материалов BFM.ru

Ключевые выводы:
- Материалы BFM.ru в целом можно воспроизводить без существенных ограничений по объёму и срокам публикации
- Для интернет-изданий обязательна гиперссылка на первоисточник
- Предварительное согласие на перепечатку материалов BFM.ru не требуется
- Ограничение касается не собственных материалов BFM, а контента партнёров и агентств, публикуемого по лицензии
- Отдельно запрещается полнотекстовая ретрансляция существенных объёмов новостного потока, особенно если сайт индексируется поисковиками и новостными агрегаторами

Для ВКР:
- Допустимо использовать RSS и HTML-страницы для внутреннего анализа
- Допустимо использовать статьи как контекст для `RAG`
- В продукте надо обязательно давать ссылку на оригинал
- Нельзя делать полнотекстовую ретрансляцию потока пользователю
- Нужно особенно внимательно относиться к заметкам, которые могут быть основаны на агентских материалах партнёров

Нормализованное значение для БД:
- `legal_status = "public_rss"`

Примечание:
- Юридически источник выглядит одним из самых удобных для исследования и `MVP`, но ограничение на полнотекстовую ретрансляцию всё равно нужно учитывать в продуктовой логике

## 4. Что реально отдаёт источник

### 4.1. Структура ответа

По предоставленному живому фиду:

```xml
<item>
  <title>Захарова: Россия предупредила балтийские страны из-за пролёта в их небе дронов ВСУ</title>
  <link>https://www.bfm.ru/news/602941</link>
  <description>«Их предупредили. Не поймут — получат ответ», — заявила официальный представитель российского МИДа</description>
  <pubDate>Mon, 06 Apr 2026 20:12:18 +0300</pubDate>
  <author>Сердар Овлякулиев</author>
  <category domain="https://www.bfm.ru/rubric/politics">Политика</category>
  <category domain="https://www.bfm.ru/news?type=news&author=27328">Сердар Овлякулиев</category>
</item>
```

### 4.2. Ключевые наблюдения

- `link` выглядит чистым и коротким: `https://www.bfm.ru/news/{id}`
- `description` содержит короткий лид, а не полный текст
- `author` присутствует в RSS
- `<category>` смешивает как минимум два типа меток:
  - рубрика (`/rubric/politics`, `Финансы`, `Рынки`, `Общество`)
  - ссылка на автора (`/news?...author=...`)
- это значит, что категории из RSS надо разбирать аккуратно: не все `<category>` являются тематическими тегами
- `pubDate` в `+0300`, значит в системе всё равно сохраняем в UTC
- подтверждено тестом:
  - `guid` отсутствует
  - `enclosure` / `thumbnail` в RSS отсутствуют
  - `ETag` и `Last-Modified` не поддерживаются
  - фид содержит `50` записей

### 4.3. Поля, которые надо брать в коллектор

| Поле Jarvis | Откуда брать |
|-------------|--------------|
| `url` | `entry.link` |
| `canonical_url` | нормализованный `entry.link` |
| `title` | `entry.title` |
| `content` | full text со страницы статьи |
| `snippet_lead` | `entry.summary` / `description` |
| `published_at` | `entry.published_parsed` |
| `author` | `entry.author` |
| `tags` | только рубричные `<category>`, не author-category |
| `raw_content` | HTML страницы статьи |

## 5. robots.txt и техническая вежливость

Источник:
- `https://www.bfm.ru/robots.txt`

Ключевые директивы:

```txt
User-agent: *
Disallow: /ajax
Disallow: /preview
Disallow: /search
Disallow: /users
Disallow: *search=*

Host: https://www.bfm.ru
Sitemap: https://www.bfm.ru/sitemap.xml
```

Что это значит для нас:

| Директива | Значение | Действие коллектора |
|-----------|----------|---------------------|
| `/search` и `*search=*` | поисковые URL запрещены | не использовать поисковые страницы |
| `/ajax`, `/preview`, `/users` | служебные разделы запрещены | не трогать |
| запрета на `/news/{id}` нет | страницы новостей разрешены | можно ходить за полным текстом |
| `Crawl-delay` отсутствует | явного ограничения нет | использовать `crawl_delay = 1.0` как вежливый дефолт |

Итог:
- За HTML-страницами новостей ходить можно
- Основной RSS-фид выглядит безопасным для работы
- Надо избегать любых служебных и поисковых URL

## 6. Извлечение полного текста

Нужно ли идти на страницу:
- `да`

Рекомендуемая стратегия:
1. Сохранить `description` как `snippet_lead`
2. Скачать HTML страницы статьи по `canonical_url`
3. Попробовать `trafilatura.bare_extraction(..., favor_precision=True)`
4. Если текста мало, попробовать `favor_recall=True`
5. Если extraction плохой, искать стабильный BS4 fallback по HTML-структуре BFM

Что подтверждено тестом:
- HTML статический
- `trafilatura` справляется с full-text extraction
- `Playwright` не нужен

Что надо учитывать:
- `trafilatura` может захватывать шум боковой колонки, например строку `Лента новостей`
- после extraction нужен пост-процессинг, который вырезает такие служебные строки
- paywall в протестированном материале не обнаружен, но на большей выборке это ещё нужно наблюдать

## 7. Дедупликация и каноникализация

Предварительные правила:
- `link` выглядит уже каноничным URL статьи
- query-параметров в самом RSS URL статьи не видно
- можно использовать обычную каноникализацию: `https`, lowercase host, без trailing slash

Особенность:
- категории автора нельзя смешивать с тематическими рубриками
- дубликаты, вероятно, будут ловиться в основном по URL и title_hash

Итог:
- `canonical_url` строится из `entry.link`
- `title_hash` полезен как стандартная страховка
- `event_cluster_id` будет особенно полезен при сравнении BFM с РБК, Коммерсантом, РИА и ТАСС

## 9. Мониторинг здоровья

Что может сломаться:
- RSS может изменить структуру `<category>`
- автор может перестать приходить в `<author>`
- full-text extraction со страницы может начать возвращать мусор
- HTML может стать JS-heavy

Минимальные health-check сигналы:
- RSS отвечает `200`
- есть записи
- даты корректно парсятся
- `author` извлекается хотя бы у части записей
- full text хотя бы одной статьи извлекается

Нормальные значения:
- `items в фиде`: `50`
- `author coverage`: `50/50`
- `guid coverage`: `0/50`
- `thumbnail coverage`: `0/50`
- `ETag`: нет
- `Last-Modified`: нет
- `full text`: около `1000` символов для протестированной новости

## 10. Итоговые правила для коллектора

```text
1. Забрать RSS по URL https://www.bfm.ru/news.rss?type=news
2. Для URL статьи использовать entry.link
3. Для canonical_url использовать стандартную нормализацию URL
4. snippet_lead брать из description
5. За полным текстом ходить на HTML-страницу статьи
6. В categories отделять рубрики от author-category
7. Author брать из entry.author
8. Для full text сначала использовать trafilatura, затем очищать шумовые строки вроде «Лента новостей»
9. При плохом extraction всё равно сохранять новость с snippet_lead
```
