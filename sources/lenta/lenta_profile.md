## 1. Зачем этот источник

Lenta.ru — один из старейших русскоязычных новостных порталов (основан 1999).
Широкий охват: политика, экономика, общество, наука, технологии, культура.

Что даёт «Джарвису»:
- Оперативная лента: ~100 новостей в день, 24/7
- Широкая тематика — покрывает то, чего нет у Хабра
- Есть имена журналистов (поле `<author>`) — можно анализировать авторство
- Структурированные редакционные рубрики через `<category>`

Контент быстрый: короткие новостные заметки (300-800 слов), публикуются часто.
Это `information_type = "daily"`, не аналитика.

## 3. Что реально отдаёт RSS (исследование живого фида)

**Проверено:** `https://lenta.ru/rss` (апрель 2026)

Структура одного `<item>`:

```xml
<item>
  <guid>https://lenta.ru/news/2026/04/03/moskvicha-predskazali-ne-sovsem-laskovuyu-pogodu/</guid>
  <author>Варвара Кошечкина</author>
  <title>Москвичам предсказали «не совсем ласковую» погоду</title>

  <!-- link = guid, без UTM-параметров -->
  <link>https://lenta.ru/news/2026/04/03/moskvicha-predskazali-ne-sovsem-laskovuyu-pogodu/</link>

  <!-- description ПУСТОЙ — это особенность Lenta.ru -->
  <description><![CDATA[]]></description>

  <!-- pubDate в МОСКОВСКОМ ВРЕМЕНИ (+0300), НЕ UTC -->
  <pubDate>Fri, 03 Apr 2026 18:54:49 +0300</pubDate>

  <!-- thumbnail статьи -->
  <enclosure url="https://icdn.lenta.ru/images/..." type="image/jpeg" length="39342"/>

  <!-- один редакционный раздел -->
  <category>Экономика</category>
</item>
```

### Ключевые наблюдения

**`<description>` пустой.** `<![CDATA[]]>` — Lenta.ru не кладёт никакого контента в RSS.
Нет даже лида. Полный текст можно получить ТОЛЬКО со страницы статьи.
Если страница недоступна — у нас нет вообще ничего (нет fallback summary как у Хабра).

**`<guid>` = `<link>`.** Один и тот же чистый URL без UTM-параметров.
Нет двойственности как у Хабра. Canonical URL — просто нормализация (https, без trailing slash).

**`<pubDate>` в московском времени (`+0300`), не UTC.**
`18:54:49 +0300` = `15:54:49 UTC`. feedparser конвертирует автоматически:
`entry.published_parsed` всегда возвращает UTC struct_time.
Наш `calendar.timegm()` работает корректно — часовой пояс учтён feedparser'ом.

**`<author>` — полное имя журналиста** (Варвара Кошечкина, Олег Давыдов...).
Ценные метаданные. У Хабра был username, у Ленты — ФИО или имя.

**`<enclosure>` — URL превью-картинки статьи.**
feedparser кладёт в `entry.enclosures[0].url`. Можно сохранять в `extra` JSONB
для отображения thumbnail в UI без дополнительного HTTP-запроса.

**`<category>` — один редакционный раздел.**
«Экономика», «Интернет и СМИ», «Наука и техника», «Ценности» и т.д.
Только один тег (в отличие от Хабра с несколькими). Это официальная рубрикация редакции.

## 4. robots.txt (исследование)

Источник: `https://lenta.ru/robots.txt` (апрель 2026)

```
User-agent: *
Disallow: /search
Disallow: /check_ed
Disallow: /auth
Disallow: /my
Disallow: /core
Disallow: */2020/02/13/money/
Disallow: */?rcmclid=
Disallow: /?
Disallow: */twz/zdorovie/
Disallow: */twz/krugozor/
Disallow: */twz/interaktiv/

Sitemap: https://lenta.ru/sitemap.xml.gz
```

### Что это значит для нас

| Директива | Что значит | Наше действие |
|-----------|-----------|---------------|
| **Нет `Crawl-delay`** | Явного ограничения нет | Используем `crawl_delay = 1.0` (вежливый дефолт) |
| `Disallow: */?rcmclid=` | URL с трекинг-параметром запрещены | Использовать чистый URL (guid = link, UTM нет) |
| `Disallow: /?` | Главная с query-параметрами | Нас не касается |
| `Disallow: /search` | Поиск закрыт | Нас не касается |
| Страницы `/news/...` | НЕ в Disallow | Ходить за полным текстом можно |

**Вывод:** ходить на страницы статей (`/news/2026/04/03/...`) **легально** и без ограничений
по Crawl-delay. Используем `1.0 сек` как вежливый минимум.

## 5. Путь одной статьи: от RSS до базы

```
[RSS-фид Lenta.ru]
  │
  ├── GET https://lenta.ru/rss
  │   Заголовки: User-Agent, If-None-Match, If-Modified-Since
  │   (Lenta поддерживает ETag — проверить при первом запуске)
  │
  ├── Если 304 Not Modified → выходим
  │
  ├── Если 200 OK → парсим через feedparser
  │
  └── Для каждого <item>:

      ├── Извлечь URL
      │   entry.link == entry.id (guid) — одинаковые, без UTM
      │   Canonical URL = нормализация: https, без trailing slash
      │
      ├── Дедупликация
      │   Проверить canonical_url в базе → пропустить если есть
      │   Проверить title_hash (MD5 lowercase) → кластер если похожий
      │
      ├── Получить полный текст (ОБЯЗАТЕЛЬНО — description пустой)
      │   GET на canonical_url
      │   Ждать: crawl_delay = 1.0 сек
      │   trafilatura.bare_extraction(html, favor_precision=True)
      │   Если текст < 200 символов → favor_recall=True
      │   Если всё равно пусто → статья без контента, пометить quality='low'
      │   ⚠️ Нет fallback summary — если страница недоступна, контента нет вообще
      │
      ├── Извлечь метаданные
      │   title   ← entry.title
      │   author  ← entry.author (полное имя журналиста)
      │   category← entry.tags[0] (один раздел)
      │   date    ← entry.published_parsed → calendar.timegm() → UTC datetime
      │             (+0300 → feedparser конвертирует в UTC автоматически)
      │   image   ← entry.enclosures[0].url (thumbnail для UI)
      │
      └── Сохранить
          INSERT INTO news (url, canonical_url, title, content, snippet_lead,
                            published_at, source_id, channel_type, ...)
          INSERT INTO news_raw (news_id, raw_content='html', raw_format='html')
```

## 6. Извлечение полного текста: особенности Lenta.ru

Lenta — стандартный статический HTML-сайт. Playwright не нужен.
trafilatura справляется хорошо: новостные заметки с плотным текстом.

**Потенциальные проблемы:**
- Короткие заметки (100-300 слов): trafilatura может счесть их «мало текста»,
  переключиться на favor_recall и захватить лишнего. Порог 200 символов достаточен.
- Статьи с большим количеством врезок и цитат: проверить на реальных примерах.
- Статьи-галереи (много фото, мало текста): контент будет скудным — нормально.

## 7. Дедупликация

Lenta.ru — уникальные URL для каждой новости. Дубликатов в рамках одного источника нет.

Кросс-источниковая дедупликация (с ТАСС, РИА, другими):
- Одно событие → несколько источников пишут об одном
- `title_hash` (MD5 lowercase) поможет поймать почти идентичные заголовки
- Семантическая дедупликация — задача Слоя 2

## 8. Расписание опроса

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| `crawl_interval` | 30 минут | ~100 новостей/день = ~2 новости в час → опрашивать чаще |
| `crawl_delay` | 1.0 сек | Нет Crawl-delay в robots.txt, вежливый дефолт |
| `priority` | `high` | Оперативные новости, нужны быстро |

**Расчёт:** 100 новостей/день при 48 опросах в сутки (каждые 30 мин) = ~2 новые
статьи за опрос. С `limit` по умолчанию (сколько отдаёт сервер) — достаточно.

## 9. Мониторинг здоровья

**Что может сломаться:**
- Пустой `<description>` — если вдруг начнут его заполнять, это улучшение, не поломка
- Изменение структуры HTML страниц статей → trafilatura перестанет извлекать текст
- Смена URL-схемы новостей (маловероятно для старого сайта)

**Метрики здоровья:**
- `articles_last_24h` — норма: 80-120. Если 0 при обычном >80 → проблема
- `avg_content_length` — норма для коротких новостей Ленты: 500-3000 символов.
  Если вдруг <200 → trafilatura сломалась
- `articles_with_no_content` — если >10% за сутки → проблема с извлечением текста

## 12. Результаты тестирования (апрель 2026)

Запущен `test_lenta.py`:
- HTTP 200, размер фида: 143,518 байт (меньше Хабра: 270K)
- Записей в фиде: 200 ✓
- **ETag поддерживается**: `W/"32655fd1c90b74d596b8230cee67f498"` (слабый ETag)
- **Last-Modified не возвращается** — сервер просто не отправляет этот заголовок
- description пустой: `''` (0 символов) ✓ подтверждено
- thumbnail: присутствует в enclosure ✓
- Дата: `19:08:46 +0300` → feedparser → `16:08:46 UTC` ✓ конвертация верная
- trafilatura (favor_precision): 1,233 символов из HTML 53,053 — типичная короткая новость
- author: полное имя журналиста «Кирилл Луцюк» ✓

**Почему даты хранятся в UTC, а не в московском времени:**
`TIMESTAMPTZ` в PostgreSQL всегда хранит UTC. Это стандарт — база не знает
в каком часовом поясе живёт пользователь. Отображение в московском времени —
задача UI/API: `SELECT published_at AT TIME ZONE 'Europe/Moscow'`.

## 13. Итоговые правила для коллектора

```text
1. Забрать RSS по URL https://lenta.ru/rss
2. Для URL статьи использовать link/guid — они совпадают
3. Не рассчитывать на description: он пустой, поэтому full-text fetch обязателен
4. За полным текстом ходить на HTML-страницу статьи
5. Для текста использовать trafilatura; при неудаче оставить пустой content, но не терять запись
6. В metadata сохранять author, category, thumbnail, extraction_method
7. Playwright не нужен, HTML статический
8. Источник считать широким ежедневным новостным потоком общего назначения
```
